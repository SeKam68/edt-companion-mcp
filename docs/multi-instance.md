# Два экземпляра EDT с разными проектами

Как одновременно работать через edt-companion-mcp с двумя (или более) открытыми экземплярами EDT, каждый — со своим проектом.

## Почему нужна настройка

Плагин — это OSGi-бандл, который живёт **внутри процесса EDT**. При активации он поднимает HTTP-сервер на `127.0.0.1:6868` и работает **только над тем workspace, который открыт в этом экземпляре EDT** — отдельного процесса 1С он не запускает.

Отсюда ограничение: два экземпляра EDT не могут одновременно слушать один порт. Второй бандл не сможет занять `6868`, его `activate()` упадёт с `BindException`, и у второго инстанса MCP-сервера просто не будет.

Решение — **выделить каждому экземпляру свой порт**.

## Порядок настройки

### 1. Порт для каждого инстанса

Порт резолвится в таком порядке:

1. system property `-Dedt.yaxunit.mcp.port=<порт>`;
2. env-переменная `EDT_YAXUNIT_MCP_PORT`;
3. **интерактивная настройка** на странице **Window → Preferences → edt-companion-mcp**;
4. компилированный дефолт `6868`.

`-D`-проперти и env имеют приоритет над настройкой из окна (чтобы headless/CI-запуск оставался предсказуемым). Некорректные значения (не число, вне диапазона 1–65535) игнорируются с предупреждением в stderr, резолв уходит на настройку/дефолт.

- **EDT #1 (проект A)** — оставить дефолт `6868`, ничего настраивать не нужно.
- **EDT #2 (проект B)** — задать другой порт, например `6869`.

#### Способ 1 (рекомендуемый): окно настроек EDT

**Window → Preferences → edt-companion-mcp → TCP-порт HTTP-сервера** → ввести `6869` → **Apply**. Порт применяется **сразу**: сервер перезапускается на новом порту без рестарта EDT. Значение хранится в настройках workspace этого инстанса.

Если введённый порт занят другим процессом, сервер останется остановленным (сообщение в stderr/Error Log) — введите свободный порт.

#### Способ 2: `eclipse.ini` / переменная окружения

Для CI/автозапуска или когда окно недоступно. В `eclipse.ini` этого инстанса (или в отдельном ярлыке/лаунчере) добавить строку в секцию **после** `-vmargs`:

```
-Dedt.yaxunit.mcp.port=6869
```

либо экспортировать переменную в шелле, из которого стартует второй EDT:

```
set EDT_YAXUNIT_MCP_PORT=6869   # Windows cmd
$env:EDT_YAXUNIT_MCP_PORT=6869  # PowerShell
export EDT_YAXUNIT_MCP_PORT=6869 # bash
```

При этом способе порт фиксируется на старте — смена требует рестарта инстанса, а настройка в окне игнорируется (проперти/env приоритетнее).

### 2. Проверка живости

После запуска обоих экземпляров:

```
curl http://127.0.0.1:6868/health
curl http://127.0.0.1:6869/health
```

Оба должны отдать `{"status":"ok","tools":39}`. Если по одному из портов `connection refused` / 404 — соответствующий EDT не запущен, бандл не активирован или порт занят чем-то другим.

### 3. Два сервера в `.mcp.json`

Завести **два отдельных MCP-сервера**, каждый на свой URL:

```jsonc
{
  "mcpServers": {
    "edt-companion-A": { "type": "http", "url": "http://127.0.0.1:6868/mcp" },
    "edt-companion-B": { "type": "http", "url": "http://127.0.0.1:6869/mcp" }
  }
}
```

Инструменты придут с разными префиксами — `mcp__edt-companion-A__*` и `mcp__edt-companion-B__*`, так что не спутаешь, к какому проекту идёт вызов.

## Оговорки

- **Один workspace на инстанс.** Каждый сервер видит только объекты своего EDT-workspace и его несохранённые правки. Кросс-проектных запросов между двумя серверами нет — если нужен объект из проекта B, обращайся к серверу B.
- **Оба проекта в одном workspace.** Если оба проекта открыты в одном экземпляре EDT, второй сервер не нужен: `list_workspace_projects` покажет оба проекта, и один сервер на `6868` работает с обоими. Разные порты нужны именно для **разных процессов EDT**.
- **Масштабирование.** Тот же приём работает для трёх и более инстансов — по уникальному порту и записи в `.mcp.json` на каждый.
